Research

User behavior data, onboarding metrics, and competitor analysis

User data and feedback revealed early drop-offs driven by lack of context and trust. These insights defined the key focus areas for the onboarding redesign.

Clarity first
Users need to understand what the product does before committing.
Habit apps show benefits before sign-up. AI tools preview the experience before interaction. Coaching apps explain value before asking for personal data.
Users are more likely to continue when the purpose is clear.
Trust before commitment
Entering a phone number felt high-risk without enough reassurance.
Headspace / Calm build trust through guided intro screens. Duolingo explains value before account creation. Notion AI shows examples before asking for input.
Trust signals are critical before asking for personal information.
Progress & momentum
The SMS-only flow had no visible steps or completion cues.
Users didn't know how long setup takes, what comes next, or when they finish. Products with strong onboarding show steps, progress, and outcome.
Momentum reduces drop-off.
How might we
"How might we design an onboarding experience that builds trust, provides clarity, and drives users to complete setup with confidence?"
Iteration

I tracked drop-offs in Amplitude after each ship, identified exactly where users left, and iterated the flow in two rounds before it worked.

v1 — Early flow  ·  Wk 1

Designed initial flows, reviewed and aligned with the team on direction and key user needs.

Data from Wk 1
53% dropped at step 1
The phone number ask came cold. Users had no context for the product or why it needed their number. No trust had been built yet.
The tradeoff
Longer flow, higher trust
Moving the number ask to the end meant more steps. But users who got there were already invested. Completion rate mattered more than funnel length.
What changed
Coach selection first
Opening with a coach selection made the experience feel personal from the start. The number ask at the end felt earned, not intrusive.
v2 — Revised flow  ·  Wk 2

Redesigned based on Wk 1 data. Moved coach selection to step 1 to build trust early, pushed the phone number ask to the end of the flow.

Wk 3  — Drop-off data from v1 pointed to four specific problems: the progress bar gave no step clarity, habit selection felt like being bucketed into a list, coach cards were text-heavy with no personality, and there was no clear way to connect with the AI coach.

Wk 4  — Shipped the redesign and tracked via Amplitude. Replaced text-heavy coach cards with personality-first video previews. Swapped the list-style habit picker for a visual icon grid — chosen for, not bucketed. Added two ways to connect: phone call or text. Drop-off at step 2 fell significantly.

Reality check
It took 3 iterations to get the flow right. The first version still had too much text. The second version had confusing button placement. The third version worked.
Final solution
Coach personality

Style selection before habits appear, making the AI feel personal from tap one.

Habit selection

Visual icon tiles replaced a plain list, making selection feel like curation.

Device connect

Quick-connect and manual setup both available, removing a hard blocker.

Progress bar

"Step 2 of 4" labels cut mid-flow drop-off by making the end feel reachable.

Impact

Tracked post-launch in Amplitude. Onboarding completion climbed from a 95% drop-off rate to a sustained 34.2% completion, with every step showing double-digit lift.

02 — Habit Building Interface

Designing the habit tracker and daily check-in experience

The problem

Users could add habits via chat, but there was no visual tracker. Everything lived in Google Sheets on the backend.

Before — habit names and weekly tracking lived in a Google Sheet
Light mode Dark mode
What I built
→
Calendar view tracker
Designed a simple habit tracker with calendar view. Created a full iteration flow: add → edit → delete → mark complete.
→
Light & dark mode
Designed both from day one because users check in at night and bright screens felt intrusive.
→
Emoji picker for personalization
Built emoji picker for habit personalization. A small change that made a big difference in engagement.
→
Cursor UI patterns
Implemented cursor UI patterns for quick, low-friction interactions.
Key design decisions
Calendar view: Initially designed a list view (easier to code), but users wanted to see their streaks visually. Switched to a calendar grid after feedback.
Emojis: Text-only habits felt boring. Small change, big impact on engagement.
Light/Dark mode: Built both from day one because users check in at night and bright screens felt intrusive.
Skipped advanced filtering (not enough users yet)
Kept it to 5 habits max initially (simplified the UI)
No animations in v1 (faster to ship, added later)

Ongoing

The product has 6 AI coaches with different personalities: Maya, Sarah, Anne, Sergeant Grindmode, Bro Coach, Alex. I designed the visual language for each:

04 — Design System

Weeks 2–12, Ongoing

"With a team of 2 engineers and 1 designer, we needed reusable components to ship fast without redesigning everything."
— Why I built this first
What I created
Component library in Figma with semantic versioning
Design tokens for colors, typography, spacing, shadows
Documentation in Notion for developer handoff
Cursor integration for auto-generating code from designs
Core components
Buttons — primary, secondary, text, disabled states
Input fields — text, number, emoji picker
Cards — habit cards, coach cards, stats cards
Navigation — bottom nav, top bar, modals
Typography system — headings, body, labels
Color system — light/dark mode, semantic colors
How it's used
→
Engineers pull directly from Figma
Components are built to spec, no back-and-forth about sizing or spacing.
→
Cursor AI generates initial code
Cursor AI generates initial code from component specs, then we iterate in dev and update Figma to match.
Reality check
The design system is about 70% complete. I'm still documenting edge cases and adding components as we need them. It's not perfect, but it's functional and saves us hours every week.

Learnings

What I learned from this project

01
AI product design is different
You can't control the output, so you design the container (UI patterns, tone, structure) and let the AI fill it in.
02
Simplicity wins
Tried complex interactions in v1: animations, micro-interactions. Users didn't care. They wanted it to work, not look fancy.
03
Voice interfaces are hard
Still figuring out how to design for audio-first experiences. It's a learning process.
04
Being the first designer means wearing all the hats
Brand, product, marketing, systems. You do everything. It's chaotic but you learn fast.
